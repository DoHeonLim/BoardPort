# 신고 처리와 제재 운영 정책

BoardPort의 신고 처리는 단순히 신고 상태를 바꾸는 기능이 아니라, 운영 판단과 감사 로그를 함께 남기는 흐름입니다.

## 1. 목표

- 신고 대상과 신고 사유를 명확히 기록
- 관리자가 처리 결과를 일관되게 선택
- 제재, 삭제, 경고 같은 후속 조치를 추적
- 감사 로그로 운영 이력을 남김

## 2. 신고 대상

- 상품
- 게시글
- 댓글/리뷰
- 방송/VOD
- 채팅 메시지
- 사용자 프로필 또는 활동

## 3. 처리 상태

- `PENDING`: 처리 대기
- `PROCESSING`: transaction 안에서 단일 처리자가 선점한 임시 상태
- `RESOLVED`: 조치 완료
- `DISMISSED`: 신고 기각

`PROCESSING`은 외부에 장시간 유지하는 작업 상태가 아닙니다. 신고 claim과 최종 조치는 같은 transaction에서 commit되며, 실패하면 `PENDING`으로 함께 롤백됩니다.

## 4. 사유별 기본 추천 조치

| 신고 사유       | 기본 추천 조치 | strike |
| --------------- | -------------- | ------ |
| `SPAM`          | 3일 일시 정지  | 1      |
| `INAPPROPRIATE` | 콘텐츠 삭제    | 1      |
| `ABUSIVE`       | 경고           | 1      |
| `SCAM`          | 7일 일시 정지  | 2      |
| `OTHER`         | 경고           | 1      |

오신고는 관리자가 `DISMISSED`로 기각합니다. 위 표는 누적 strike를 반영하기 전의 기본 추천이며, 최근 90일 누적치에 따라 정지 기간이 상향될 수 있습니다.

## 5. 선택 가능한 조치와 누적 기준

신고 승인 시 관리자는 신고 내용과 추천값을 확인한 뒤 다음 항목 중 하나를 기본 조치로 선택하며, 콘텐츠 대상의 정지 조치에는 콘텐츠 삭제를 함께 적용할 수 있습니다.

- `WARN`: 사용자 경고
- `DELETE_CONTENT`: 신고 대상 콘텐츠 삭제
- `TEMP_BAN`: 기간을 지정한 일시 정지
- `PERMA_BAN`: 영구 정지

USER 대상 신고는 삭제할 직접 콘텐츠가 없으므로 `DELETE_CONTENT` 선택지와 콘텐츠 삭제 병행 옵션에서 제외합니다. 기본 추천이 `DELETE_CONTENT`인 경우에는 `WARN`으로 보정합니다. 콘텐츠 대상 신고에서는 `TEMP_BAN` 또는 `PERMA_BAN`과 콘텐츠 삭제를 함께 적용할 수 있습니다.

조치는 경고 → 삭제 → 정지 순서로 자동 승급되지 않습니다. `getRecommendedResolution()`은 사유별 기본 strike와 최근 90일 누적 strike를 합산해, 합계가 2 이상이면 3일, 3 이상이면 7일, 4 이상이면 30일 정지를 추천합니다. 사유별 기본 정지 기간보다 낮은 추천은 만들지 않습니다.

자동 제재보다 관리자 확인을 우선하며, 조치 사유는 감사 로그에 남깁니다.

## 6. 감사 로그

관리자 조치는 AuditLog에 남깁니다.

기록 기준:

- 관리자 ID
- 대상 타입과 ID
- 수행 액션
- 재시도 가능한 신고 조치의 멱등 키
- 사유
- 조치 시각

누적 strike는 별도 전용 테이블이 아니라 최근 90일의 `ADD_STRIKE` 감사 로그를 기준으로 계산합니다.

오조치가 확인되면 사용자 제재는 해제하고 그 사유를 감사 로그에 남깁니다. 관리자 콘텐츠 조치는 물리적 삭제를 사용하므로 자동 복구를 지원하지 않으며, 삭제 오조치는 별도 운영 절차로 대응합니다.

## 7. 설계 판단

- 신고 상태와 후속 조치 유형을 구분해 관리자가 명시적으로 선택
- 관리자 화면에서 신고 대상 상세로 바로 이동할 수 있게 링크 제공
