# 신고 처리와 제재 운영 정책

BoardPort의 신고 처리는 단순히 신고 상태를 바꾸는 기능이 아니라, 운영 판단과 감사 로그를 함께 남기는 흐름입니다.

## 1. 목표

- 신고 대상과 신고 사유를 명확히 기록
- 관리자가 처리 결과를 일관되게 선택
- 제재, 숨김, 경고 같은 후속 조치를 추적
- 감사 로그로 운영 이력을 남김

## 2. 신고 대상

- 상품
- 게시글
- 댓글/리뷰
- 방송/VOD
- 채팅 메시지
- 사용자 프로필 또는 활동

## 3. 처리 상태

- `PENDING`: 처리 대기
- `RESOLVED`: 조치 완료
- `DISMISSED`: 신고 기각

## 4. 처리 기준

| 상황 | 권장 조치 |
| --- | --- |
| 명백한 스팸/홍보 | 콘텐츠 숨김, 경고 |
| 사기 의심 거래 | 콘텐츠 숨김, 유저 제재 검토 |
| 욕설/혐오/괴롭힘 | 경고 또는 일시 정지 |
| 반복 위반 | 정지 기간 상향 |
| 오신고 | 신고 기각 |

## 5. 제재 단계

제재는 신고 내용, 반복 여부, 피해 가능성을 기준으로 단계적으로 적용합니다.

1. 경고: 경미한 위반 또는 첫 위반
2. 콘텐츠 숨김: 스팸, 사기 의심, 명백한 정책 위반 콘텐츠
3. 일시 정지: 반복 위반 또는 사용자 피해 가능성이 큰 경우
4. 영구 정지 검토: 사기, 악의적 반복 위반, 심각한 괴롭힘

자동 제재보다 관리자 확인을 우선하며, 조치 사유는 감사 로그에 남깁니다.

## 6. 감사 로그

관리자 조치는 AuditLog에 남깁니다.

기록 기준:

- 관리자 ID
- 대상 타입과 ID
- 수행 액션
- 사유
- 조치 시각

누적 위반 횟수는 별도 전용 테이블이 아니라 감사 로그의 제재 기록을 기준으로 추적합니다.

오조치가 확인되면 제재 해제 또는 콘텐츠 복구 조치를 수행하고, 복구 사유도 감사 로그에 남깁니다.

## 7. 설계 판단

- 신고 처리와 실제 제재를 분리해 오조치 위험 감소
- 관리자 화면에서 신고 대상 상세로 바로 이동할 수 있게 링크 제공
