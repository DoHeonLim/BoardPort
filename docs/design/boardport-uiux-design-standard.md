# BoardPort UI/UX 디자인 기준

BoardPort의 UI 기준은 반복해서 쓰는 거래·채팅·방송·관리 화면의 정보 배치와 조작 방식에 맞췄습니다.

## 1. 디자인 방향

BoardPort의 디자인 방향은 **Harbor Minimalism**을 기준으로 정했습니다.
보드게임 거래, 채팅, 방송, 알림처럼 많은 기능이 한곳에 모이더라도 사용자가 현재 위치와 다음 행동을 명확히 알 수 있는 화면을 목표로 합니다.

참고: [Harbor Minimalism 상세 디자인 기준](https://northern-pastry-e08.notion.site/BoardPort-UI-UX-Design-Standard-v1-2-2e4d5334deb18035adc3f1a02dc8b914?pvs=74)

- 모바일에서 먼저 편해야 함
- 정보 밀도는 높이되, 카드와 메타 정보의 우선순위를 명확히 함
- 라이트/다크 모드 모두에서 같은 기능 위계를 유지
- 거래, 채팅, 방송, 관리자 화면이 서로 다른 앱처럼 보이지 않게 함

## 2. 레이아웃 규칙

- 주요 탭은 하단 TabBar 기준으로 유지
- 탭 이름은 상품·게시글·채팅·방송·내 정보로 표시
- 상세 화면은 모바일에서 풀페이지 우선, 필요한 경우 모달/시트 사용
- 관리자 화면은 마케팅형 레이아웃보다 작업형 정보 배치 우선
- 카드 안에 또 다른 큰 카드 구조를 반복하지 않음
- 버튼, 칩, 메타 정보가 좁은 폭에서 겹치지 않도록 고정 영역과 말줄임 기준을 둠

## 3. 컴포넌트 계약

### 카드

상품, 게시글, 방송 카드는 아래 순서를 유지합니다.

1. 썸네일 또는 대표 상태
2. 분류/상태/권한 배지
3. 제목
4. 핵심 메타
5. 시간 또는 활동 기준 시점

메타 아이콘은 도메인마다 다른 문법을 쓰지 않고, 좋아요/댓글/조회수 기준을 통일합니다.

### 목록

- 목록은 스캔 가능해야 하며, 버튼보다 콘텐츠 정보가 먼저 읽혀야 함
- 무한 스크롤은 탐색 흐름이 중요한 상품/게시글/방송에 사용
- 명시적 페이지 이동은 보드게임 도감처럼 “특정 페이지로 점프”가 필요한 목록에 사용
- 상품·게시글 목록 상단 도구는 560px 미만에서 두 줄, 이상에서 한 줄 배치
- 모바일 상품 목록은 첫 줄에 상품 수·보드게임 도감, 둘째 줄에 정렬·보기 방식 유지

### 상태 화면

빈 상태, 권한 없음, 삭제된 콘텐츠, 로딩 상태는 도메인별 문구를 다르게 하되 구조는 통일합니다.

- 무엇이 없는지
- 사용자가 다음에 할 수 있는 행동
- 뒤로가기 또는 홈 이동 경로

### 공통 헤더·폼·모달

- `SubpageHeader`: 작성·수정 화면의 헤더 구조 공유, 뒤로가기 동작은 호출 화면에서 전달
- `ViewModeToggle`: 리스트·그리드 버튼과 `aria-pressed` 상태 공유, 선택값은 화면에서 URL과 연결
- `OptionalFormSection`: 선택 입력의 접기·펼치기와 검증 오류 발생 시 외부 펼침 제어
- `Button`: 서버 폼 제출과 클라이언트 비동기 작업의 진행 문구·비활성 상태 공유
- `ModalCloseButton`: 모달 닫기 버튼의 모양과 접근성 이름 제공

### 관심 목록

- 상품·게시글·다시보기 탭으로 구분하고 찜한 시각을 기준으로 정렬·표시
- 상품·게시글은 리스트/그리드 전환, 다시보기는 그리드로 제공
- 찜 해제는 작은 휴지통 버튼으로 제공하고 접근성 이름으로 동작 설명
- 이미지 위의 삭제 버튼 때문에 제목·가격·하단 정보 전체에 빈 공간이 생기지 않도록 배치
- 다시보기의 연결 보드게임 배지는 이미지 좌측 하단에 표시

## 4. 인터랙션 규칙

- 모바일 터치 타깃은 최소 44px 기준
- hover만으로 가능한 기능은 모바일 대체 동작을 제공
- 삭제·제재처럼 되돌리기 어려운 작업은 확인 단계를 둠
- focus-visible을 유지해 키보드 탐색이 가능하도록 함
- motion은 상태 전환을 보조하는 수준으로 사용하고, 핵심 조작을 가리지 않음

터치 영역은 아이콘의 시각적 크기와 구분합니다. 목록 보기 전환 버튼과 정렬 선택은 최소 44px 영역을 사용하며, 카드의 소형 보조 버튼은 별도 점검 대상입니다.

공용 바텀시트와 팔로우 목록에는 200ms 전환을 적용합니다. 조건부 모달은 `ModalPresence`로 닫힘 상태를 전달한 뒤 제거해 퇴장 전환을 유지합니다. 닫히는 시트는 `inert`로 조작을 막고, 기존 포커스는 닫힘 시점에 복귀하며 스크롤 잠금은 퇴장 후 해제합니다. 동작 줄이기 설정에서는 CSS 전환과 JS 퇴장 대기를 생략합니다.

퇴장 유지, 포커스·스크롤 복귀와 움직임 줄이기의 검증 범위는 [테스트 전략](../operations/testing-strategy.md#모바일-ui-회귀)을 따릅니다.

참고: [토스 인터랙션 사례](https://toss.tech/article/interaction)는 행동 안내와 피드백에 모션을 활용하며, [Apple 동작 줄이기 기준](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/reduced-motion-evaluation-criteria/)은 사용자 설정 반영을 강조합니다. 목록 전체의 반복 등장 효과보다는 시트 전환·버튼 상태처럼 조작 결과를 설명하는 곳을 우선합니다.

[Google 터치 영역 가이드](https://support.google.com/accessibility/android/answer/7101858?hl=en)는 아이콘의 시각적 크기와 터치 영역을 구분합니다. 네이티브 권장 단위(dp)를 웹 px와 동일시하지 않고, 프로젝트의 44px 기준에 이 원칙을 적용합니다.

## 5. 다크모드

다크모드에서도 제목, 본문, 보조 정보가 구분되도록 색상과 대비를 조정했습니다.

- 본문 텍스트와 보조 텍스트 대비 확보
- 경계선은 너무 강하지 않게 유지
- 상태 배지는 라이트/다크 모두에서 의미가 유지되도록 색상 역할을 고정
- 카드 내부 이미지와 배지가 겹칠 때 배경 tint를 사용해 가독성 확보

## 6. 카피 규칙

- 기능 설명보다 사용자가 지금 해야 할 행동을 먼저 보여줌
- 오류 문구는 원인과 다음 행동을 함께 제공
- 운영/제재 문구는 감정적 표현보다 명확한 상태 전달 우선
- 앱 내부에서 “기능 설명서”처럼 보이는 문장을 과하게 노출하지 않음
- 주요 기능명은 상품·게시글·채팅·방송·거래 후기처럼 동작이 드러나는 용어 사용
- 인증 화면의 일부 제목 등 브랜드 표현과 실제 기능 버튼의 이름은 구분

## 7. 소셜 미리보기

제품, 게시글, 방송 공유 이미지는 같은 브랜드 문법을 유지합니다.

- 대표 이미지 또는 썸네일 우선
- 제목과 상태 정보는 짧게
- 크롤러가 접근 가능한 고정 `/og-image` 경로 제공
- 미리보기 이미지는 실제 콘텐츠를 가리는 장식보다 정보 전달 우선

## 8. 디자인 토큰 방향

BoardPort의 시각 요소는 화면별 임의 스타일보다 역할 기반 토큰을 우선합니다.

- 색상은 브랜드 색보다 역할을 먼저 정의: `primary`, `surface`, `border`, `muted`, `danger`, `success`
- spacing과 radius는 카드, 버튼, 시트, 모달에서 반복 가능한 기준으로 유지
- 상태 배지는 색상 자체보다 의미 역할을 우선
- 라이트/다크 모드는 같은 역할 토큰을 기준으로 값만 다르게 적용

## 9. QA 체크리스트

- 모바일 390px 폭에서 메타/배지/버튼 겹침 없음
- 목록 도구는 360·427·559·560·634·640·768px에서도 겹침과 가로 넘침 확인
- 라이트/다크 모드에서 텍스트 대비 유지
- TabBar, 버튼, 시트, 모달의 터치 타깃 확인
- 긴 제목, 긴 태그, 긴 카테고리명 말줄임 확인
- 이미지 없는 카드, 삭제된 콘텐츠, 권한 없음 상태 확인
