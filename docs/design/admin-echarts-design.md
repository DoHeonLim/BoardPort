# 관리자 ECharts 설계

BoardPort 관리자 화면은 활동 통계 조회, 신고 처리, 유저 제재, 방송 모니터링, 상품/게시글 관리를 지원합니다.

ECharts로 활동 추이와 신고 분포를 표시하고, 관련 처리 목록으로 이동할 수 있게 구성했습니다.

## 1. 도입 목적

KPI 카드와 테이블만으로는 아래 질문에 빠르게 답하기 어렵습니다.

- 최근 서비스 활동이 유지되고 있는가
- 신고 큐가 쌓이고 있는가
- 어떤 신고 사유가 많이 들어오는가
- 방송은 어느 정도 생성되고 종료되는가
- 유저 유입과 제재 상태는 어떤 흐름인가

그래서 관리자 화면은 아래 흐름을 기준으로 구성했습니다.

1. **KPI:** 현재 상태 숫자 확인
2. **Chart:** 추이와 분포 파악
3. **List:** 실제 처리 대상 확인
4. **Action:** 신고 처리, 제재, 상세 이동

## 2. 적용 범위

- 관리자 홈
  - 회원, 신고, 상품, 게시글, 방송 요약
  - 최근 30일 활동 추이
  - 운영 처리 상태

- 신고 관리
  - 신고 상태 분포
  - 신고 사유 상위 항목
  - 처리 대기 큐

- 방송 관리
  - 방송 상태별 분포
  - 최근 방송 생성/종료 추이

- 유저 관리
  - 가입 추이
  - 정지/활성 상태 요약

## 3. 구현 기준

- page는 화면 조합에 집중
- 집계 로직은 `actions`와 `service` 계층으로 분리
- 차트 옵션은 도메인별 컴포넌트에 분산하지 않고 공통 옵션 빌더로 정리
- 차트는 초기 관리자 화면 부하를 줄이기 위해 필요한 단위로 지연 로딩
- KPI와 차트에서 실제 목록으로 이어지는 링크를 제공

## 4. 디자인 기준

- 관리자 화면은 통계와 처리 대상을 빠르게 찾을 수 있도록 배치
- 툴팁은 배경과 구분되는 불투명 패널 사용
- 다크모드에서도 축, 범례, 격자선이 데이터를 가리지 않게 대비 조정
- 모바일에서는 차트보다 KPI와 처리 목록의 접근성을 우선

## 5. 차트 사용 기준

추이나 분포를 비교하는 항목에 차트를 사용합니다.

- 시간 흐름이 중요한 데이터는 선 차트 사용
- 상태별 분포는 막대 또는 원형 차트 사용
- 신고 사유처럼 비교가 필요한 항목은 막대 차트 우선
- 단일 숫자는 차트보다 KPI 카드로 표시
- 차트 클릭 또는 관련 링크를 통해 실제 처리 목록으로 이동 가능해야 함

## 6. 주요 설계 포인트

- 활동 추이와 신고 분포를 처리 대상 목록과 함께 제공
- 도메인별 집계 기준을 service 계층으로 분리
- ECharts 옵션 재사용과 라이트/다크 테마 대응
- 차트가 실제 처리 액션으로 이어지도록 정보 구조 설계
